# Multi-model AI: Gemini, Groq and Muse

## Concepts (kept separate in code)
- **Provider** – who serves the API: `gemini`, `groq`, `openai` (`src/server/ai-providers.ts`).
- **Model** – the underlying weights, identified as `provider:modelId` (`src/lib/ai-catalog.ts`).
- **Agent** – what people @mention: `@Muse`, `@Gemini`, `@Llama`, `@Agent` (legacy "Room agent").
- **Credential source** – `environment` (GEMINI_API_KEY / GROQ_API_KEY / OPENAI_API_KEY), `workspace` (the existing encrypted per-workspace OpenAI key) or `demo` (no model; fixed sample text, always labeled DEMO).

Muse is not a model. Its replies are generated by the Gemini or Groq model an owner selects, and every reply shows that model.

## Behaviour
- Backend resolves agent -> model (`agentTarget` in `src/server/ai-workspace.ts`) at enqueue and again when the job runs. Members can only use approved, enabled, configured models.
- Only catalog models can be approved. New workspaces approve free-plan Gemini models and Groq GPT-OSS 20B; conditional Llama models require owner approval after checking account eligibility. Model-list visibility does not prove free access. OpenAI is paid and requires the owner's explicit "authorize paid usage" setting. A failed provider request never retries on a different model/provider.
- Per-channel FIFO, one running job per channel, idempotency keys, replay and artifact history are unchanged. New agent/provider/model fields ride on the same persisted events.
- Limits: 4,000-char prompts, 12k-char context (Muse: 30k chars, 300 messages), 1,024 output tokens (Muse 2,048), per-member hourly and per-workspace daily request caps (owner-configurable, defaults 30/h and 300/day), the existing monthly token quota, a 6/min socket rate limit, and a process-local per-model request guard plus a provider cooldown after a 429.
- Errors: provider failures become safe messages (raw SDK text is never forwarded); one retry for transient errors before any text streams; partial streams are kept and marked incomplete; quota reservations are released when the provider rejected the call before generating.
- Muse reads only the current channel (`messages WHERE room_id = ?`). Artifacts from Muse/Gemini/Llama use an `<artifact ...>` block that the server parses, validates and saves; it is hidden from the streamed chat text.
- Schema v6 is additive (new table + nullable columns); a timestamped backup is taken before migrating. Workspaces that already saved an OpenAI credential are migrated with paid usage authorized so they keep working.

## Environment
`GEMINI_API_KEY`, `GROQ_API_KEY` (server only), plus existing `AUTH_*`, `WORKSPACE_CREDENTIAL_KEY`, optional `OPENAI_API_KEY`/`OPENAI_MODEL`.

## Tests
`npm test` (mocked SDKs; proves routing/permissions/limits, not real API access), `npm run test:e2e`, and `npm run test:live` (real Gemini generation plus a Groq-backed Muse request through the queue in an in-memory workspace; needs keys; skipped otherwise). Live tests explicitly load `.env.local` despite test-mode environment rules. The owner-controls browser test verifies saved settings, missing-key errors, disabled options, and desktop/mobile panels without using real provider keys.

Live verification on 2026-10-30 succeeded for Gemini 3.8 Flash and Groq GPT-OSS 20B. Groq-backed Muse recalled a stored channel fact and persisted its streamed answer and token usage with paid authorization disabled. Google rejected Gemini 2.5 Flash as unavailable to new users, although it appeared in model listing. Defaults now use Gemini 3.8 Flash / 3.5 Flash-Lite; saved workspace choices and old model IDs are preserved. Owners of workspaces with saved legacy settings should explicitly approve/select a current model.

## Model IDs
Catalog IDs were rechecked against [Google pricing](https://ai.google.dev/gemini-api/docs/pricing), [Groq models](https://console.groq.com/docs/models), and [Groq limits](https://console.groq.com/docs/rate-limits) on 2026-10-30. Groq lists `llama-3.3-70b-versatile` and `llama-3.1-8b-instant` with enterprise pricing and omits them from its free-plan table, so Llama is conditional and no longer approved by default in new workspaces. Existing saved approvals remain intact. Owners must verify their account plan before approving Llama; a model-list check cannot confirm billing eligibility. Groq GPT-OSS 20B/120B are listed with free-plan limits. The live Groq test probes GPT-OSS 20B, not Llama. Successful/failed model-list checks update connected workspace clients, and empty or failed checks prevent affected models from being queued.
